# Orchestration moves out of Go into a live dispatcher agent driving the harness Workflow tool; Go keeps the state store and git mechanics

`pb dispatch` ran the implementation loop as a Go engine that spawned one cold `claude --print` subprocess per ready issue. Each subprocess paid a full cold start — re-read its skill, re-booted MCP, and explored the repo from scratch with zero shared context — so the wall-clock cost scaled badly as plans grew. Worse, the headless `--print` mode cannot ask a question: a worker that hit a genuine human decision had nowhere to go, and the engine's AFK-label selection gate exited early when nothing was AFK-labeled, so plans stalled silently with no operator in the loop. The engine was slow and stuck-prone for the same root reason — it was a one-shot batch process with no live agent steering it.

We move orchestration out of Go and into a **live dispatcher agent**: the `bender-implement-prd` skill drives the harness **Workflow** tool, authoring a JS orchestration script that runs a deterministic DAG loop-until-stable (scout ready ids → spawn parallel warm workers → merge → re-scout) over warm sub-agents instead of cold subprocesses. Go is demoted to the state store + git mechanics: status ownership, the planrepo, and the dependency-ordered merge-back, now exposed as a standalone `pba merge`. A first-class `needs-input` status persists parked human decisions across runs; the dispatcher batch-interviews them between rounds and `retry`-resumes them to `todo`. The AFK/HITL labels are demoted from selection gates to escalation hints — readiness is now purely the dependency graph plus status.

## Considered options

- **Keep the Go engine, swap cold `--print` for a warm pool.** Reuses the existing selection/merge code, but the headless subprocess still can't ask a question, and the AFK-gate stall is independent of warmth. It treats the symptom (cold start) and not the cause (no live agent, no human-decision channel). Half-fix.
- **Keep orchestration in Go but add an interactive escalation IPC.** Lets a worker surface a decision back to the engine, but rebuilds in Go the interview/loop logic the harness Workflow tool already gives us for free, and still ports nothing useful — the engine remains the thing fighting the harness rather than using it.
- **Live dispatcher agent on the harness Workflow tool (chosen).** The harness already runs warm sub-agents, collects validated structured outcomes, and can pause to ask the operator. Letting the agent own the loop and leaving Go only the deterministic state/git work removes both failure modes at once and deletes orchestration code rather than adding it.

## Consequences

- **The dispatcher path is Claude-Code-specific.** The harness Workflow tool only exists in Claude Code, so the live-dispatcher path does **not** port to the `pi` agent target. The trade-off is accepted as an opt-in: the **worker** skill (`bender-implement-issue`) stays portable across agents, so only the orchestration layer is bound to Claude Code.
- **`pb dispatch` is removed — a breaking change.** The Go orchestration engine and its `pb dispatch` / `pba dispatch` commands are gone, documented as a breaking change with a release-note entry.
- **The single long-running dispatch process and its per-slug flock are gone.** Previously one dispatch process held the per-slug `.dispatch.lock` for the whole run (ADR-0003). Now `pba merge` re-acquires that flock per round and releases it, and the dispatcher holds a separate **advisory** cross-run lock (`.dispatcher.lock`) so two dispatcher sessions don't drive the same plan at once. The two locks are deliberately distinct — if the dispatcher held `.dispatch.lock` for the whole run, the merger could never acquire it.
- **`needs-input` is first-class and persistent.** Parked decisions survive across runs and are excluded from readiness, so a stuck plan stalls visibly at `needs-input` rather than silently — and a resolved decision is written back into the issue JSON so a future worker won't re-hit it.
- **Readiness is label-agnostic.** AFK/HITL no longer gate which issues are selected; they only tune a worker's escalation threshold. Readiness is the dependency graph plus status, which removes the "nothing AFK-labeled → early exit" stall.
- **ADR-0003's merge-back strategy is preserved.** The dependency-ordered merge in a dedicated per-slug integration worktree, never touching the parent repo's HEAD, is unchanged — it simply moves behind `pba merge` and is invoked once per round by the dispatcher instead of inline by the Go loop.
