# Skill templates are per-skill directories; the flat override contract is a breaking change

Skill templates were flat files: `internal/template/embedded/{name}.skill.tmpl` rendered to a single `{name}/SKILL.md`, and project overrides lived flat at `.plan-bender/templates/{name}.skill.tmpl`. To let a skill ship supporting files alongside its body (e.g. a `CONTEXT-FORMAT.md` the `SKILL.md` references), we make a skill template a **directory**: `embedded/{name}/SKILL.md.tmpl` plus any number of supporting files at any depth. The loader walks the dir recursively; files ending in `.tmpl` are rendered through the existing engine, everything else is copied verbatim. Because a generated skill is exposed as a whole-directory symlink, supporting files reach the agent with no change to the symlink, dispatch, or doctor code.

## Considered options

- **Additive flat + `_assets/{name}/` subdir.** Keep the flat `*.skill.tmpl` files untouched and add a parallel assets tree keyed by skill. Fully backward-compatible — existing flat overrides keep working. Rejected: it splits a single skill's source across two locations, and the generated/installed forms are already per-skill directories, so the source staying flat is the odd one out. The cost of the additive approach is permanent divergence between source and output layout; the cost of the directory approach is a one-time migration. We chose the one-time cost.
- **Inline include directive instead of sibling files.** A `{{ include "CONTEXT-FORMAT.md" }}` function that pastes content into the rendered `SKILL.md`, producing one self-contained file. Rejected: it fights the canonical skill layout, where `SKILL.md` references supporting files by relative path and the agent reads them on demand (progressive disclosure). Inlining defeats that and bloats the body.
- **Allow a verbatim `SKILL.md` as the body.** Marker becomes "contains `SKILL.md.tmpl` or `SKILL.md`." Rejected: it introduces a both-files-present ambiguity to resolve for a case no skill needs. The body is always `SKILL.md.tmpl`; a template with no variables passes through the engine unchanged, so requiring the suffix costs authors nothing.
- **Auto-migrate flat overrides.** On generate, `git mv` any stale `.plan-bender/templates/{name}.skill.tmpl` into `{name}/SKILL.md.tmpl`. Rejected for v1: silently mutating the user's files is the kind of surprise this project avoids, and it raises a both-locations-exist conflict. A warning that converts the silent failure into a loud one is enough; auto-migration can follow if anyone asks.

## Consequences

- **Breaking change to the override contract.** A flat `.plan-bender/templates/{name}.skill.tmpl` is no longer read; customizations must move to `.plan-bender/templates/{name}/SKILL.md.tmpl`. Left silent this would make a user's fork vanish without a word, so generate/setup emit a stderr warning for any lingering flat `*.skill.tmpl`, naming the file and the new path, and continue with the bundled template.
- **Two distinct override warnings now coexist.** Location staleness (flat file ignored → move to `{name}/`) and content staleness (`bender-implement-prd` / `bender-orchestrator` forks should re-fork for `pba next`). The latter is updated to inspect the new `{name}/SKILL.md.tmpl` location.
- **`LoadTemplates` returns `map[string]Skill`** keyed by skill name, where `Skill` is a flat bag of files (relpath → content, including `SKILL.md.tmpl`). The body marker `SKILL.md.tmpl` is required; validity is checked *post-merge*, so a partial override that supplies only a supporting file is legal. Two source files that would write the same output path (e.g. `X.tmpl` and `X`) are an error.
- **Generation is now a destructive per-skill rebuild.** `GenerateSkills` removes `.plan-bender/skills/{agent}/{name}` before rewriting it, so a supporting file removed from the template does not linger in the generated skill. Whole-skill orphan cleanup (e.g. a backend-gated skill left behind when Linear is disabled) is a pre-existing gap and is deliberately not addressed here.
- **`symlinkSkills`, dispatch's `linkSkills`, and `doctor` are untouched.** All three operate on whole skill directories, so supporting files travel through the existing symlinks automatically.
- **Test churn in `internal/template/templates_test.go`.** Map keys move from `"{name}.skill.tmpl"` to `"{name}"`, and body access goes through a `Main()` accessor. Mechanical, confined to that file plus `generate_test.go`.
